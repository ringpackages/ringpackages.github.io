Appendix

Quick introduction to Ring

More than one system

A Ring program that uses .NET runs on Windows and on Linux, and should run on macOS. Most of it is the same everywhere, and a few things are not. This lesson shows the output of one program on Windows and on Linux, explains the differences, and gives a short list for writing programs that work on both.

What you will learn#

  • what is the same on every system and what is not,
  • how a program asks which system it is on (isWindows(), isLinux(), isMacOSX()),
  • paths, upper and lower case in file names, and the end of a line,
  • how to keep a feature of one system (a window) away from the others,
  • a checklist for a portable program.

What works where#

WindowsLinuxmacOS
Text, numbers, dates, collections, LINQyesyesshould work
Files, folders, streams, compression, JSON, XMLyesyesshould work
HTTP, sockets, web servers, databases (SQLite, EF Core)yesyesshould work
Windows Forms and WPF (windows, controls, drawing)yesnono
The registry, Access (OLEDB), named shared memoryyesnono

The package was tested on Windows and on Linux (Ubuntu 24.04, x64, .NET 9). macOS and arm64 were not tested, so the last column says "should work", not "works". The extension is a C library that is built once for each system; the steps are in Getting started.

Windows Forms and WPF are made of the Windows system, so nothing in the package can bring them to another system. The classes are in the package, but they need the Windows desktop part of .NET, and a Linux computer does not have it. A Windows-only program (a window, a clipboard, a tray icon) has to say that it is.

The program#

It asks the system six questions and prints the answers. The program is the same on every system:

samples/UsingDotNet/tutorials/ch13_systems.ring
# one program for Windows, Linux and macOS - what differs between the systems and how a program asks instead of assuming
#   (the answers are different on each system; the lesson shows the output of Windows and of Linux)
load "dotnet.ring"

using {
	"System"
	"System.IO"
}

# A window needs Windows: on another system, asking for it ends the program at once, so the line that asks is behind a question.
if isWindows()
	using { "System.Windows.Forms" }
ok

func main

	# 1. Which system? Ring answers with isWindows(), isLinux() and isMacOSX(); .NET names the platform
	? "1. windows: " + isWindows() + ", linux: " + isLinux() + ", macos: " + isMacOSX() + ", platform: " + new Environment().OSVersion.Platform

	# 2. Paths. A path separator is \ on Windows and / on Linux and macOS; Path.Combine uses the right one, and a / is accepted by every system.
	? "2. separator: " + new Path().DirectorySeparatorChar + "   Combine: " + new Path().Combine(["data","report.txt"])

	# 3. Case. Windows does not care about upper and lower case in a file name, Linux does (macOS usually does not, but can).
	cFolder = new Path().Combine([new Path().GetTempPath(),"ringdotnet-systems"])
	new Directory().CreateDirectory(cFolder)
	cFile = new Path().Combine([cFolder,"notes.txt"])
	new File().WriteAllText([ :path = cFile, :contents = "x" ])
	? "3. notes.txt exists: " + new File().Exists(cFile) + ", NOTES.TXT exists: " + new File().Exists(new Path().Combine([cFolder,"NOTES.TXT"]))
	new Directory().Delete([ :path = cFolder, :recursive = true ])

	# 4. The end of a line: 2 characters on Windows (13 10), 1 on Linux and macOS (10)
	? "4. the end of a line has " + len(new Environment().NewLine) + " character(s)"

	# 5. The folder of the user is found by asking, not by writing C:\Users\ or /home/
	cHome = new Environment().GetFolderPath("UserProfile")
	? "5. the home folder exists: " + new Directory().Exists(cHome)

	# 6. A feature of one system, behind a question
	if isWindows()
		oForm = new Form
		? "6. a window can be made: " + classname(oForm)
	else
		? "6. no windows here: the program works in the console"
	ok

Windows prints:

2. separator: /   Combine: data/report.txt
3. notes.txt exists: 1, NOTES.TXT exists: 0
4. the end of a line has 1 character(s)
5. the home folder exists: 1
6. no windows here: the program works in the console

How it works#

1. Ask which system#

isWindows(), isLinux() and isMacOSX() are functions of Ring. .NET answers too: Environment.OSVersion.Platform is Win32NT on Windows and Unix on Linux and macOS. Use the Ring functions for a choice in the program, and the .NET ones when the platform is only to be shown.

2. Paths#

Windows writes data\report.txt and Linux writes data/report.txt. Do not write the separator yourself: Path.Combine joins the parts with the right one. A / is accepted by every system, also on Windows, so a path in the program text can be written with /. A path that starts with a letter and a colon (C:\) or one that starts with /home/ exists on one system only; take the folders from the system instead (see 5 below, the tutorial Paths and the environment and File information).

3. Upper and lower case#

On Windows notes.txt and NOTES.TXT are the same file. On Linux they are two names, and the second one does not exist. A program that works on Windows by luck (it opens Config.JSON and the file is config.json) stops with a file not found error on Linux. Write the name of a file the same way everywhere, and prefer lower case names.

4. The end of a line#

Windows ends a line with two characters (13 and 10), Linux and macOS with one (10). Environment.NewLine is the right one for the system. File.ReadAllLines reads both kinds (the tutorial Text files and encodings), so a program that only reads lines does not notice. Notice it when you count characters, compare files byte by byte or write a file for another system.

5. Ask the system for a folder#

Environment.GetFolderPath("UserProfile") is C:\Users\Ann on Windows and /home/ann on Linux. Path.GetTempPath() is the folder for temporary files. The names ApplicationData, LocalApplicationData and MyDocuments work the same way.

6. Keep a feature of one system behind a question#

The most important line of the program is at the top:

Ring
if isWindows()
	using { "System.Windows.Forms" }
ok

On Linux, using { "System.Windows.Forms" } does not give an error that the program can catch: the runtime of .NET cannot start the desktop part, prints the message You must install or update .NET to run this application... Microsoft.WindowsDesktop.App... No frameworks were found and the program ends. A program that has a window mode and a console mode puts every using and every new Form behind isWindows().

A checklist for a program for every system#

  1. Paths with Path.Combine and folders from GetFolderPath; no C:\ and no \.
  2. File names the same way every time, and lower case.
  3. Windows-only features (windows, registry, clipboard, tray icon, Access, named shared memory) behind isWindows(), with a message or a console version for the others.
  4. Commands of the system chosen with isWindows(): cmd /c dir or sh -c ls (the tutorial Time, tasks and other programs).
  5. Time zone names: Windows has Eastern Standard Time and Linux has America/New_York; see Time zones.
  6. Tests on both systems, or at least a look at the output of one program on the other system. A difference such as the one in step 3 shows only when the program runs.
Note

System.Drawing (pictures, Bitmap, Graphics) is a Windows feature in current versions of .NET. A program that must make pictures on Linux needs a package that does not use it, such as SkiaSharp (the lesson Pictures on every system).

What you learned#

  • text, files, network and data work everywhere; windows and the registry are Windows-only,
  • isWindows(), isLinux() and isMacOSX() ask the system,
  • Path.Combine, GetFolderPath and NewLine give the right answer for each system,
  • a window feature must be behind isWindows(), because on Linux the program cannot recover from asking for it,
  • a checklist for programs that run everywhere.

Exercises#

  1. Run the program on a computer with another system (or a Linux system under WSL) and compare the output with the two blocks above.
  2. Add a seventh question: what does Path.GetTempPath() start with?
  3. Make a function configPath() that returns the path of settings.json inside the folder ApplicationData of the user, for every system.
  4. Write a program that prints Windows in a window when it can and in the console when it cannot.

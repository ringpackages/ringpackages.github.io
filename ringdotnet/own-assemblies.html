Appendix

Quick introduction to Ring

Your own assemblies

Wrap any .NET DLL — your own library or a NuGet package — with one command, and use its classes with the same simple syntax as the built-in ones.

Two ways to use an assembly#

WayWhen
Generic calls — dnLoad, dnType, dnNew, callMethoda quick call, nothing to generate
Generated classes — wrapassembly.ringthe simple oObj.Method() syntax, properties, events, enums, inheritance

The examples of this page use the small C# library of the package, samples/UsingDotNet/tests/UserLib (the namespace MyCompany.Tools, the class Calculator). Build it once with the .NET SDK, and run the Ring programs from the folder of the package:

Shell
dotnet build samples/UsingDotNet/tests/UserLib -c Release -o samples/UsingDotNet/tests/UserLib/bin

Generic calls#

Ring
load "dotnet.ring"
dnLoad("samples/UsingDotNet/tests/UserLib/bin/UserLib.dll")     # dependencies are found next to the dll

oCalc = dnNew("MyCompany.Tools.Calculator",[10])
oCalc.callMethod("Add",[5])
? oCalc.getProp("Total")                              # 15
? dnStatic("MyCompany.Tools.Calculator","Square",[7]) # 49

Generated classes#

Generate Ring classes for every public type of the DLL:

Shell
cd tools/dotnettools
ring wrapassembly.ring ../../samples/UsingDotNet/tests/UserLib/bin/UserLib.dll ../../myclasses

This writes two files for each namespace into myclasses/: a loader and the classes (and classindex.ring, the index of the classes, when every namespace is wrapped). Use them like any other wrapped namespace:

Ring
load "dotnet.ring"
dnLoad("samples/UsingDotNet/tests/UserLib/bin/UserLib.dll")
dnImportFrom("myclasses/","MyCompany.Tools")

oCalc = new Calculator()
oCalc.Add(10).Multiply(3)                             # fluent: methods that return a wrapped class return that class
? oCalc.Total                                         # 30
oCalc.Name = "mine"                                   # a property
? new Calculator().Square(7)                          # a static method
? oCalc.Describe([ :level = "High", :prefix = "Sum" ])                      # an enum as a string, an optional parameter
aDivide = oCalc.TryDivide(4)                          # out parameters come back in a list
? aDivide[2]

The generated classes support the same things as the built-in ones: real inheritance, properties as attributes, setXXXEvent() for events, enums as strings, overloads as one method with a hash list of parameters (Name([ :param = value ])), optional parameters and out / ref results.

The example in the package#

samples/UsingDotNet/tests/UserLib is a complete example — a small C# library, the generator run on it, and a test that uses it (samples/UsingDotNet/tests/test_userassembly.ring).

using System;
using System.Linq;
using System.Collections.Generic;

namespace MyCompany.Tools
{
	public enum Level { Low, Medium, High }

	public class Calculator
	{
		public double Total { get; private set; }
		public string Name { get; set; } = "calc";
		public event EventHandler Changed;

		public Calculator() { }
		public Calculator(double start) { Total = start; }

		public Calculator Add(double value) { Total += value; Changed?.Invoke(this, EventArgs.Empty); return this; }
		public Calculator Multiply(double value) { Total *= value; return this; }
		public static int Square(int x) { return x * x; }
		/* a method called Init: Ring uses init for the constructor of a generated class, so the method is @Init */
		public string Init(string mode) { return "init " + mode; }
		/* a params array may be left out: it is empty */
		public static string Join(string separator, params string[] parts) { return string.Join(separator, parts); }
		public static string EnumName(Enum value) { return value.GetType().Name + "." + value; }
		public string Describe(Level level, string prefix = "Total") { return prefix + "=" + Total + " (" + level + ")"; }
		public bool TryDivide(double by, out double result)
		{
			result = 0;
			if (by == 0) return false;
			result = Total / by;
			return true;
		}
		public List<string> Words(string text) { return new List<string>(text.Split(' ')); }
		/* a method that returns exactly List<object>: the bridge must hand it over as an object (ObjectList), not as a Ring list */
		public List<object> Mixed() { return new List<object> { 1, "two", 3.5 }; }
		/* generic methods whose type argument the arguments do not show: Ring gives it as a type name (callGeneric) */
		public static T Parse<T>(string text) { return (T)Convert.ChangeType(text, typeof(T), System.Globalization.CultureInfo.InvariantCulture); }
		public T Create<T>() where T : new() { return new T(); }
		/* closed generic types that have no class of their own: the class of the generic definition wraps them */
		public Dictionary<string, int> Counts() { return new Dictionary<string, int> { { "a", 1 }, { "b", 2 } }; }
		/* a nested type: its class is named after the types around it (CalculatorMemory) */
		public class Memory
		{
			public double Stored { get; set; }
			public string Label() { return "stored " + Stored; }
		}
		public Memory Remember() { return new Memory { Stored = Total }; }
		public SortedSet<double> Sorted() { return new SortedSet<double> { 3.5, 1.5 }; }
	}

	// A ref struct of the library: Ring gives a text, the struct is made for the call from the text (its constructor)
	public readonly ref struct Cursor
	{
		private readonly ReadOnlySpan<char> text;
		public Cursor(ReadOnlySpan<char> text) { this.text = text; }
		public int Length { get { return text.Length; } }
		public int Count(char c) { int n = 0; foreach (char x in text) if (x == c) n++; return n; }
	}

	// ref structs that a method returns: a ref struct enumerator is answered as a list of its items, a ref struct with a text method as the text
	public ref struct WordEnumerator
	{
		private ReadOnlySpan<char> rest;
		public WordEnumerator(ReadOnlySpan<char> text) { rest = text; Current = default; }
		public ReadOnlySpan<char> Current { get; private set; }
		public WordEnumerator GetEnumerator() { return this; }
		public bool MoveNext()
		{
			rest = rest.TrimStart();
			if (rest.IsEmpty) return false;
			int end = rest.IndexOf(' ');
			if (end < 0) end = rest.Length;
			Current = rest.Slice(0, end);
			rest = rest.Slice(end);
			return true;
		}
	}

		private readonly ReadOnlySpan<char> name;
		public Label(ReadOnlySpan<char> name) { this.name = name; }
		public string Render() { return "[" + name.ToString() + "]"; }

	public static class Spans
	{
		/* an IAsyncEnumerable result: Ring reads it with toList() or asyncEnumerator() */
		public static async System.Collections.Generic.IAsyncEnumerable<int> CountAsync(int n)
		{
			for (int i = 1; i <= n; i++)
			{
				await System.Threading.Tasks.Task.Delay(1);
				yield return i * 10;
			}
		}
		/* a ref return through the IL path (a Span parameter): the value is read from the reference */
		public static ref int ElementAt(Span<int> data, int index) { return ref data[index]; }
		public static int TokenSize(Token token) { return token.Size; }
		public static int Disposed;
		public static Lease Take() { return new Lease(new byte[] { 9, 8, 7 }); }
		public static WordEnumerator Words(string text) { return new WordEnumerator(text); }
		public static Label MakeLabel(string name) { return new Label(name); }
		public static int CursorLength(Cursor cursor) { return cursor.Length; }
		public static int CountOf(ref Cursor cursor, char c) { return cursor.Count(c); }
		/* a Span result: answered as an array (a text for char) */
		public static ReadOnlySpan<char> Middle(string text) { return text.AsSpan(1, text.Length - 2); }
		public static Span<byte> Head(byte[] data) { return data.AsSpan(0, 2); }
		/* a span that is passed by reference */
		public static bool TrySplit(ReadOnlySpan<char> text, out ReadOnlySpan<char> rest)
		{
			int at = text.IndexOf(',');
			rest = at < 0 ? ReadOnlySpan<char>.Empty : text.Slice(at + 1);
			return at >= 0;
		}
		public static void Skip(ref ReadOnlySpan<char> text, int n) { text = text.Slice(n); }
	}

	// A class that is not public and implements two interfaces that do not inherit each other (the elements of a fluent API are like this). No interface
	// is named after the class, so Ring wraps the object with a class that has the members of both interfaces, and of their extension methods.
	public interface IChannelSource
	{
		string Read();
		int Position { get; }
	}

	public interface IChannelSink
	{
		void Write(string text);
		string Name { get; set; }
	}

	internal class Channel : IChannelSource, IChannelSink
	{
		private string data = "";
		public string Name { get; set; } = "channel";
		public int Position { get { return data.Length; } }
		public string Read() { return data; }
		public void Write(string text) { data += text; }
	}

	public static class ChannelExtensions
	{
		public static string Shout(this IChannelSource source) { return source.Read().ToUpperInvariant() + "!"; }
		public static IChannelSink Tag(this IChannelSink sink, string tag) { sink.Write("[" + tag + "]"); return sink; }
	}

dnImportFrom("json/","Newtonsoft.Json")

The tutorial A NuGet package walks through this with a real package.

A package often needs other DLLs and, sometimes, native libraries. dotnet publish copies both: the native libraries are in runtimes/<system>-<architecture>/native next to the DLL, and the bridge finds them there. The lessons from A NuGet package on use real packages: A QR code, Excel files, Pictures on every system, PDF files, Text to speech, and a project with three packages.

A class of your assembly that derives from a class of a package (PersonValidator : AbstractValidator<Person>) derives from its Ring class when the package was wrapped into the same folder before your assembly, so it has the methods of the base class, and the extension methods of the interfaces that the base class implements (oValidator.ValidateAndThrow(oPerson)). Its loader loads the namespace of the base class first.

Two DLLs of one program can share the output folder: a class of the second one that has the name of a class that is already in the folder gets the prefix of its namespace (Spectre.Console and Spectre.Console.Testing both have a StringExtensions; the second is TestingStringExtensions). Two DLLs that have the same namespace need folders of their own, or only one of them wrapped: a DLL whose classes you do not call (an extension method that you call by dnRequest) only needs dnLoad.

A package of a namespace that the library already has (Microsoft.Extensions.DependencyInjection, Microsoft.Extensions.Configuration: the NuGet DLLs are newer builds of the ASP.NET Core ones) is only loaded with dnLoad: the classes of the library wrap its objects, and wrapping the namespace again would define the same classes twice. Make its objects with dnNew("Namespace.Type",[...]) and call its extension methods with dnRequest("call",[dnType("Namespace.StaticClass"),"Method",...]) or callGeneric.

Entity Framework Core is wrapped the same way — that is how its classes were generated.

Extension methods#

An extension method of a type that is wrapped in the same run is a method of the Ring class of that type, so a fluent API reads as it does in C#:

Ring
oTable = new Table()
oTable.AddColumn("Name")            # TableExtensions.AddColumn(oTable, "Name")
oTable.AddRow(["Ann","31"])

The classes that implement an interface get the extension methods of the interface. An extension method of a closed generic type (IEstimator<ITransformer>, the extended type of ML.NET's Append<TNext>) is a method of the classes that implement the generic interface, and the type argument of the method is worked out from the arguments. wrapassembly.ring wraps the assemblies of one run (join the paths with ; for assemblies that belong together, as ML.NET and its trainers do: Microsoft.ML.Data.dll;Microsoft.ML.LightGbm.dll), so the extension methods of a type of another assembly that is not in the run (a sink of Serilog that extends a class of Serilog itself), and of a type that has no class (a generic type, string), are static calls (new StringHumanizeExtensions().Humanize("PascalCaseText")) or a callMethod on the object (oNode.callMethod("QuerySelectorAll",["li"]), the selectors of Fizzler on a node of HtmlAgilityPack).

Which namespaces to wrap#

wrapassembly.ring <dll> <folder> [namespace ...] wraps only the namespaces you list (<dll> can be several paths joined with ;). Without names, every namespace of the assembly is wrapped.

Several assemblies can go into one folder (the index of the classes keeps the types of all of them when each one is wrapped without names), or each one into a folder of its own, as the project lesson does for its three packages. An object that comes back from a namespace that was not imported is wrapped when the folder has the index: its namespace is loaded from that folder.

Rules#

  • Generated loaders use the names of the .NET classes. When a class name is also the name of a class of the library, or of another namespace of the same assembly, the generator adds the prefix of its namespace (CoreVersion) and lists the renames — see Class generator.
  • Keep the DLL and its dependencies in one folder: assemblies are resolved next to the DLL you load.
  • The runtime mode matters: a DLL that needs Windows Forms requires the desktop mode first (a using block that names System.Windows.Forms, or dnUseDesktop()).
